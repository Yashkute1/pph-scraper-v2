# PC Part Hunt Scraper v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public, secret-free Python scraper that refreshes nine Indian PC stores daily from GitHub-hosted runners into MongoDB, safely.

**Architecture:** Adapters turn each store into raw offers; pure functions normalise and group them; one module writes MongoDB behind a sanity gate; a roll-up builds one ready-made row per part. GitHub Actions runs one job per store in parallel, then the roll-up, then a report.

**Tech Stack:** Python 3.12, Scrapling 0.4.x (`Fetcher`, `StealthyFetcher`), pymongo, pytest, mongomock, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-04-scraper-design.md`

## Global Constraints

- Python 3.12. Dependencies pinned in `requirements.txt` (runtime) and `requirements-dev.txt` (tests).
- No credential, connection string, hostname of the database, affiliate code or personal email may appear in any file, log line, or commit. `MONGO_URI` comes only from the environment.
- Database name `pph_site`. Collections written: `offers`, `products_v2`, `scrape_runs`. The collection `products` is never read or written.
- Tests never touch the network or a real database.
- Workflows: every third-party action pinned to a full commit SHA; default `permissions: contents: read`; no `pull_request_target`. Only the `report` job has `contents: write`, and it receives no secrets.
- Sanity gate threshold 60%. Out of stock at `missed_runs >= 3`. Delete after 14 days unseen. History: one point per day, 90 days.
- Per-host delay 1–2 s (Amazon 3–5 s), 3 retries. Three consecutive blocked pages abort a store.
- Store names, exactly: `elitehubs, vishalperipherals, pcstudio, primeabgb, vedantcomputers, mdcomputers, theitdepot, flipkart, amazon`.
- Commits end with the session attribution lines used elsewhere in this repo.

## Review Focus

1. A listing page returns HTTP 200 with zero product cards (store redesign). Expected: the store run is `failed`, nothing is written, nothing is marked out of stock. → Task 6, Task 8.
2. A captcha or challenge page served with HTTP 200 (Amazon, Flipkart). Expected: detected as blocked, counted toward the three-strike abort. → Task 3.
3. The same product reached through different URLs (tracking parameters, Amazon `/dp/ASIN/ref=...`). Expected: one offer. → Task 2 (`canonical_url`).
4. A store's first ever run (`previous_count == 0`). Expected: the gate passes. → Task 8.
5. A database error whose message contains the connection string. Expected: logged as the exception type only. → Task 9.
